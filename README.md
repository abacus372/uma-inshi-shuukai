# 因子周回スキル差分チェッカー

ウマ娘の因子周回サポートツール。

- レース場（競馬場・コース）を1つ選ぶ
- 「本育成用」「因子周回用」それぞれの編成（サポカ最大6枚）を入力する
- 因子周回で使っている親ウマ娘の白因子を手動で追加する（任意）
- 因子周回用の編成（サポカのヒント・サポカ自身のイベント・手動追加した親因子）でしか取得できず、
  かつ選んだレース場でそもそも発動しうるスキルだけを一覧表示する

## 使い方

`index.html` をブラウザで開くだけ（サーバー不要）。**空いている枠**をクリックするとサムネイル画像付きのサポカ選択モーダルが開き（検索・レア度/タイプ絞り込み可）、選ぶたびに閉じずに次の空き枠へ自動で進むので、続けてまとめて選べる。選び終わったら「閉じる」を押す。**既に埋まっている枠**をクリックした場合はその1枚だけの差し替えになる（選ぶと自動で閉じる）。同名・同レア度・同タイプのカードでも画像が違うので判別できる。同じ編成内では同じウマ娘のカードを重複して選べない（実際のゲームの仕様に合わせている）。

編成中のサポカが自分の育成イベントでもスキルのヒント対象を増やせる場合、「5. サポカイベントの選択肢設定」にそのイベントと選択肢が出てくる。未指定なら一番上の選択肢を選んだものとして計算される。

「4. 因子周回親の白因子」では、因子周回で使っている親ウマ娘が持つ白因子（サポカ経由では分からないもの）を検索して追加できる（検索欄でEnterを押すと一番上の候補をそのまま追加）。「一覧から選んでまとめて追加」を開くと、全スキルの一覧をクリックで追加/解除でき、モーダルを閉じずに何個でも連続で選べる。数が多いときは「まとめて追加」からスキル名を改行/読点区切りで貼り付けてまとめて登録することもできる。[UMACAPTURE](https://github.com/umasagashi/umacapture)のエクスポートJSON（`{id, star}`形式の因子データ）を貼り付けると、UMACAPTURE自身の因子ID→実際のスキルへ自動変換して追加する機能もある（実際のエクスポート形式で未検証・実験的機能）。

「全部削除」ボタンで因子周回親の白因子を一括でクリアできる（確認ダイアログあり）。

UMACAPTUREのデータやスキル名一覧は、コピペだけでなく`.json`/`.csv`/`.txt`ファイルのドラッグ＆ドロップ、またはクリックしてのファイル選択でも読み込める。

「スクリーンショットから読み取る」では、画像をアップロード/貼り付け（Ctrl+V）した後に表示されるプレビュー上で**因子一覧の部分をドラッグして選択**し、選択範囲だけを切り出して（元画像の解像度から3倍に拡大して）OCR（[Tesseract.js](https://github.com/naptha/tesseract.js)、CDN経由で読み込み、画像はどこにも送信されない）にかける。デスクトップ全体のスクリーンショットのような、関係ない部分が大半を占める画像だと文字が小さすぎて実用にならないため、範囲選択が実質必須。「画像全体を読み取る」ボタンは選択が難しい場合のフォールバックとして残してあるが、精度は選択範囲を絞った場合より大きく劣る。

スキル名の一覧という閉じた語彙が分かっている強みを活かし、以下の3段階で認識精度を上げている。

1. **文字ホワイトリスト**: 全スキル名に実際に登場する文字（約760種）だけをTesseractの認識候補に制限し、見た目の近い無関係な漢字への誤認識を減らす
2. **編集距離によるあいまい一致**: 完全一致・前方一致で見つからない場合、レーベンシュタイン距離が近いスキル名を採用する（「中蟹巧者」→「中盤巧者」のような1〜2文字の誤読を拾う）
3. **部分文字列あいまい一致**: ゲームの密なリスト表示だと、隣接する2行がTesseractに改行なしで1つの塊として認識されたり、レース名因子（スキルではないため対象外）とスキル名がくっついて認識されたりすることがある（実機テストで確認済み）。この場合、文字列の中から最もよく一致する部分文字列を探して1件確定させ、残りの前後の部分に対して再帰的に同じ処理を繰り返す。これにより「中蟹巧者涼る起い」→「中盤巧者」+「滾る想い」のような2件フュージョンだけでなく、「こダービーご外差し準備」→「外差し準備」（対象外のレース名部分は無視）のような片側だけの回収もできる

あいまい一致・分割一致で追加されたものは結果に明示されるので、誤爆していないか目視で確認すること。認識できたが対応するスキルが無かった行もそのまま表示される。

短いスキル名（6文字以下）は許容編集距離を1に制限しているが、それでも「プランX」（実在のスキル）と「プランチャ☆ガナドール」（対象外のキャラ固有因子）のように、たまたま数文字が一致する無関係な短い名前同士は原理的に区別できない。これが「要確認」表示の主な理由であり、完全な解消は狙っていない。

編成・レース場・因子・イベント選択肢は「この内容を保存」でブラウザのlocalStorageに保存され、次回開いたときに自動で復元される。それとは別に「プリセット」機能で、レース場・両編成・因子・イベント選択肢をまとめて名前を付けて複数保存し、後から呼び出したり削除したりできる（例: 使っている親ウマ娘の組み合わせごとに分けて保存する）。

## データソース

- サポカのヒントスキル一覧・スキル名・スキル発動条件: [daftuyda/UmaTools](https://github.com/daftuyda/UmaTools) の `assets/support_hints.json` / `assets/skills_all.json`。GameToraを1〜3日おきに自動スクレイピングしているので随時最新に近い（`alpha123/uma-skill-tools` の `skill_data.json` は2026年3月から更新が止まっていたため乗り換えた）。
- サポカ自身のイベントの選択肢とヒント対象スキルの対応: UmaTools側には無いため、[GameTora](https://gametora.com/umamusume/supports/)の各サポカページに埋め込まれている`__NEXT_DATA__`のJSONを`build-data.js`が直接取得・解析している（553枚 x 1リクエスト、間隔を空けて実行）。一度取得したカードのイベントは変化しない前提で、次回以降は新規追加カードだけ取得する（`data/supports.json`を差分キャッシュとして利用）。
- コース形状・競馬場名（芝/ダート・距離・回りなど、ゲーム内容更新の影響を受けない静的データ）: `Z:\stacalc-local\uma-skill-tools`（[alpha123/uma-skill-tools](https://github.com/alpha123/uma-skill-tools)）の `data/course_data.json`, `data/tracknames.json` を `source-data/` にコピーして使用。
- `build-data.js` は上記を自分でHTTP取得して `data/*.json` / `data/*.js` を再生成する（引数・事前準備不要、`node build-data.js` を実行するだけ）。GitHub Actions (`.github/workflows/update-data.yml`) が毎日自動実行している。
- サポカのサムネイル画像: `download-thumbs.js` が同じくUmaToolsの `assets/support_thumbs/*.png` を `data/thumbs/` にダウンロードする（553枚・約6.7MB）。新しいカードが増えたら再実行すればよい（既存ファイルはスキップされる）。
- 因子ID→実スキルIDの対応表（`data/factormap.js`）: [UMACAPTURE](https://github.com/umasagashi/umacapture)自身が使っている公開マスタデータ（`https://data.umacapture.com/umacapture/modules.zip` 内の `factor_info.json` / `skill_info.json`）から `build-data.js` が生成する。ビルド環境に `unzip` コマンドが必要（GitHub Actions の `ubuntu-latest` には標準搭載）。

## 判定ロジックの制限

スキルの発動条件文字列（例: `ground_type==2&phase==1&blocked_side_continuetime>=2`）のうち、以下の変数だけを見て「発動しうるか」を判定している。

コースを選んだ時点で確定するもの:
- `ground_type`（芝/ダート）
- `distance_type`（距離区分: 短距離/マイル/中距離/長距離）
- `track_id`（競馬場）
- `course_distance`（距離ぴったり指定）
- `rotation`（右/左/直線）
- `is_dirtgrade`（地方競馬場ダート扱いか）

「詳細条件」で指定した場合のみ確定するもの（未指定なら常に「満たしうる」扱い）:
- `running_style`（脚質。逃げ⇔大逃げは同一視するゲーム側の仕様も反映済み）
- `season`（季節）
- `ground_condition`（馬場状態）
- `weather`（天気）

それ以外の条件（コーナー、直線、順位、HPなど、展開や馬の作り次第でどうにでもなるもの）は常に「満たしうる」として扱い、除外条件には使っていない。そのため「有効」判定はやや甘め（=見逃しは少ないが、実際は発動しにくいスキルも混ざりうる）。

## スキルの説明文

各スキル名の下に、発動条件を含む公式の説明文（`skills_all.json`の`jpdesc`）をそのまま表示している。脚質・距離区分・コース等の条件はここに自然な日本語で書かれているので、生の条件文字列（`distance_type==2&...`）を自前で翻訳する必要がない。

## スキルの種別バッジ

結果一覧の各スキル名の左に「白」「金」「固有」のバッジを表示している。元データ（UMACAPTUREの`skill_info.json`と相関する`skills_all.json`の`rarity`値）による分類で、1=白スキル、2=金スキル（白スキルが因子の組み合わせで進化したもの）、3〜5=固有スキル。サポカのヒントは常に白スキルだが、サポカイベント・因子経由では金スキルも出てくることがあるため、見分けられるようにしている。

## 未対応（今後の課題）

- 金スキルとその元になる白スキルの直接の対応関係（「このスキルはどの白スキルから進化したか」）は、信頼できるデータソースが見つかっていないため未対応。バッジで金/白の区別はつくが、変換はできない。
- シナリオ固有の金スキル（URAファイナルズ等のシナリオ限定スキル）はサポカのヒント・イベント・因子のいずれからも取得できないため、そもそもこのツールのデータには含まれない（対応の予定なし）。
